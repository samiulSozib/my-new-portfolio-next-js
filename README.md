# Personal site and dashboard

A bilingual (English / বাংলা) personal site with a blog, projects, work history and an About page,
plus an admin dashboard to edit all of it. Built with Next.js (App Router), Neon Postgres and Vercel Blob,
and made to be hosted on Vercel.

## Stack

| Part | Choice |
| --- | --- |
| Framework | Next.js 16 (App Router), React 19, TypeScript |
| Styling | Tailwind CSS 4 |
| Database | Neon Postgres through Drizzle ORM (`@neondatabase/serverless` HTTP driver) |
| File uploads | Vercel Blob (the CV and the profile photo) |
| Auth | Email + password, bcrypt hashes, signed JWT session cookie (`jose`) |
| Social cards | `next/og` (`/{lang}/blog/{slug}/opengraph-image`) |

## Project layout

```
src/app/(site)/[lang]/   Public pages: /en, /bn, blog, tags, projects, experience, about, archive
src/app/(dashboard)/     Login, password reset, /admin/*, /account
src/app/api/             Public JSON API, newsletter signup, admin and auth endpoints
src/app/{feed.xml,sitemap.xml,robots.txt,cv}/   RSS, sitemap, robots, counted CV download
src/frontend/            Public site components, i18n dictionaries, types
src/dashboard/           Dashboard pages and components
src/server/              Database, auth, validation, data loading (server-only)
drizzle/                 SQL migrations (generated by drizzle-kit)
data/seed-data/          Starter content loaded by `npm run db:seed`
scripts/                 migrate and seed CLIs
```

## Local development

```sh
npm install
cp .env.example .env
npm run db:migrate
npm run db:seed
npm run dev
```

Open http://localhost:3000 for the site and http://localhost:3000/login for the dashboard
(`admin@example.com` / `password` unless you set `ADMIN_EMAIL` and `ADMIN_PASSWORD`).

With `DATABASE_URL` left empty, the app uses an embedded Postgres (PGlite) stored in `./.pglite`, so no
database server is needed locally. Set `DATABASE_URL` to a Neon connection string (a Neon dev branch works well)
to develop against Neon instead.

Uploads need a Vercel Blob token even locally: create a Blob store in Vercel and copy `BLOB_READ_WRITE_TOKEN`
into `.env` (or run `vercel env pull`).

## Deploying to Vercel

1. Push the repository to GitHub and import it in Vercel (framework preset: Next.js).
2. In the project's **Storage** tab, add a **Neon** database. This sets `DATABASE_URL`.
3. In the same tab, add a **Blob** store. This sets `BLOB_READ_WRITE_TOKEN`.
4. Under **Settings → Environment Variables**, add:
   - `AUTH_SECRET` — generate with `openssl rand -base64 32`
   - `APP_URL` — the public URL, for example `https://example.com`
   - `ADMIN_EMAIL`, `ADMIN_PASSWORD` — used once by the seed script
   - optional: `RESEND_API_KEY` and `MAIL_FROM` for password-reset emails, `NEWSLETTER_WEBHOOK_URL`
5. Deploy. The `vercel-build` script applies the migrations in `drizzle/` before building.
6. Seed the first admin and starter content once, from your machine:

   ```sh
   vercel env pull .env
   npm run db:seed
   ```

   Re-running the seed is safe: records are matched and updated in place. Change the admin password from
   **Account** in the dashboard afterwards.

## Database changes

Edit `src/server/db/schema.ts`, then:

```sh
npm run db:generate   # writes a new SQL migration to drizzle/
npm run db:migrate    # applies it (Vercel also runs this on every deploy)
```

## Notes

- Public pages are rendered on each request, so dashboard edits show up immediately.
- Rate limits (login, newsletter, CV download) are kept in memory per server instance, so on Vercel they are
  best effort. Use Vercel's firewall or Upstash Redis if you need strict limits.
- Without `RESEND_API_KEY`, password-reset links are written to the server log instead of emailed.
